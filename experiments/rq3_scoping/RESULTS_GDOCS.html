RQ3 History Scoping

การจำกัดขอบเขต history ยกระดับ speculatability ได้ไหม โดยไม่แตะอัลกอริทึม

[ ข้อสรุปสำคัญ ]

คำถาม การจำกัดขอบเขต history ยกระดับ speculatability ได้ไหม โดยไม่แตะอัลกอริทึม

สิ่งที่ทำ เปลี่ยน scope หลายแบบบน 6 dataset แล้ววัดสองแกนของ speculatability คือ historical support กับ prefix branching entropy ดูว่า workload ขยับไปทางไหนบนระนาบ

คำตอบมีสองท่อน

  1. แคบ scope ลงเฉย ๆ ไม่ได้ยกระดับ ทั้ง 6 dataset วิ่งไปมุมขวาล่างหมด คือ support ลดแต่ structure เพิ่ม เป็นการแลก ไม่ใช่การยกระดับ
  2. ความเกี่ยวข้องต่างหากที่ยกระดับ พอตรึงขนาด corpus ไว้เท่ากันเป๊ะแล้วเปลี่ยนแค่เนื้อหา workload ขยับไปทางขวาทั้ง 11 คู่ และ coverage เพิ่มทั้ง 11 คู่

ตัวแปรที่ใช้งานได้จริงคือ ความเกี่ยวข้องของ history ไม่ใช่ความแคบของ scope

1. วิธีทำ

สองแกนที่ใช้วัด

  • mean_support คือแกน History ในสไลด์หน้า 2 ก็คือ historical support ของ RQ1 สูงคือดี
  • 1 - normalized_branch_entropy คือแกน Structure ก็คือ prefix branching entropy ของ RQ1 แต่กลับด้าน เพราะ entropy ต่ำคือดี แกนที่ชี้ไปขวาจึงควรหมายถึงดีขึ้น
  • coverage ต้องรายงานคู่กับ support เสมอ เพราะ support เฉลี่ยเฉพาะตำแหน่งที่หา match เจอ ตำแหน่งที่หาไม่เจอถูกโยนทิ้งก่อนหาค่าเฉลี่ย datastore ที่เจอน้อยมากแต่บังเอิญไปเจอ token พื้น ๆ จึงโชว์ support สูงได้ทั้งที่ใช้งานแทบไม่ได้

speculatability สูงสุดอยู่มุมขวาบน ต่ำสุดอยู่มุมซ้ายล่าง

ทั้งสามตัววัดจาก ข้อความล้วน ๆ ไม่ต้องรัน drafter และไม่เกี่ยวกับความเร็วเลย ข้อนี้ตั้งใจ ถ้านิยาม high-speculatability ว่าเป็น dataset ที่ทดลองแล้วเร็ว ข้อสรุปจะกลายเป็น circular ทันที ในการทดลองนี้ scope ถูกนิยามด้วยการก่อสร้าง ส่วนสองแกนวัดแยกจากข้อมูล ไม่มีจุดไหนที่เอาผลลัพธ์มานิยามตัวแปรต้น

scope ที่เทียบกัน

global      history ของทุก group          เทียบได้กับ REST
group       เฉพาะ group เดียวกับ request   เทียบได้กับ DAS
local       prompt ของ request เอง        เทียบได้กับ Fast Context
narrow(N)   N เอกสารล่าสุดใน group         หั่นด้วยความใหม่แทนความเกี่ยวข้อง
control_*   สุ่มมา ขนาดเท่า treatment เป๊ะ   คู่เทียบ

เปลี่ยนแค่ก้อน token ที่เอาไป build index เท่านั้น drafter คลาสเดียว พารามิเตอร์ชุดเดียว ตลอดทั้ง 54 cells นี่คือความหมายของคำว่าไม่แตะอัลกอริทึม

ทำไมต้องมีคู่เทียบขนาดเท่ากัน

ถ้าดูแค่ global ไป group ไป local อย่างเดียว corpus หดจาก 95,367 เหลือ 87 token support ที่ลดลงจึงอธิบายได้ด้วยเหตุผลง่าย ๆ ว่าข้อความน้อยลง ไม่ใช่ว่า history เกี่ยวข้องขึ้น คนอ่านจะแย้งได้ทันทีและแย้งถูก

คู่เทียบแก้ตรงนี้ ตรึงจำนวน token ไว้เท่ากันเป๊ะ ใช้ scope key เดียวกัน มี R เท่ากัน ต่างกันแค่ว่า token ไหนอยู่ข้างใน สิ่งที่เหลือให้อธิบายจึงมีแค่ความเกี่ยวข้องอย่างเดียว

ตรวจอะไรก่อนบันทึกผลทุก cell

  • ไม่มี document จากอนาคตหลุดเข้า datastore
  • scope key หนึ่งอันต้อง map ไป datastore เดียวเท่านั้น
  • คู่เทียบมีขนาดต่างจาก treatment ไม่เกิน 1 เปอร์เซ็นต์
  • playback ต้อง reconstruct target ได้ครบ ถ้า speculation ทำให้ output เปลี่ยน ตัวเลขอื่นไม่มีความหมาย

3. ผลหลัก

A. เปลี่ยน scope แล้ว workload ขยับไปทางไหน

[ แทรกรูปตรงนี้ ]   experiments/rq3_scoping/artifacts/rq3_A_scope_movement.png
รูป A เปลี่ยน scope แล้ววัดสองแกน ลูกศรคือ global ไป group ไป local

วิธีอ่าน หนึ่ง panel ต่อหนึ่ง dataset แกนนอนคือ Structure ยิ่งขวายิ่งดี แกนตั้งคือ support เป็น log scale ยิ่งสูงยิ่งดี มุมขวาบนคือ speculatability สูงสุด สามจุดคือ global สีน้ำเงิน ไป group สีส้ม ไป local สีเขียว ลูกศรบอกทิศ ตัวเลขข้างจุดคือ coverage ไม่ใช่ความเร็ว

ผล ทั้ง 6 dataset ลูกศรวิ่งลงขวาเหมือนกันหมด ไม่มีตัวไหนวิ่งขึ้นขวาบน ตัวอย่าง CodeSearchNet support ไล่จาก 152.7 ลง 33.6 ลง 1.7 ขณะที่ structure ไล่จาก 0.374 ขึ้น 0.425 ขึ้น 0.848

เพราะฉะนั้น สรุปว่าการแคบ scope ยกระดับ speculatability ไม่ได้ มันแลก support ทิ้งเพื่อซื้อ structure และเมื่อสองแกนสวนทางกัน จะจัดอันดับได้ก็ต่อเมื่อมีสูตรรวมสองแกน ซึ่งเป็นงานของ RQ1 และยังไม่เสร็จ เราจึงหยุดที่การรายงานทิศทาง ไม่ตัดสินแทน

ข้อสรุปของ RQ3

  1. ความแคบของ scope ไม่ใช่ตัวแปรที่ยกระดับ speculatability มันแค่แลกแกนหนึ่งกับอีกแกนหนึ่ง

  3. เพราะฉะนั้นถ้าจะขยับ workload บน matrix ต้องขยับด้วยความเกี่ยวข้อง ไม่ใช่ด้วยการตัดให้เล็กลง

ตัวคุมที่ยืนยันว่ากลไกไม่ลำเอียง คือ scope global ซึ่ง treatment กับคู่เทียบ มี token ชุดเดียวกันทั้งคู่ ต่างแค่ลำดับเอกสาร ผลออกมาแทบไม่ต่างกัน ถ้าคู่นี้ออกมาต่างกันมากเมื่อไร แปลว่ากลไกคู่เทียบมีปัญหาและตัวเลขอื่นเชื่อไม่ได้

5. ภาคผนวก ผลลัพธ์และความเร็ว

ส่วนนี้ไม่ใช่คำตอบของ RQ3 แต่เก็บไว้เพราะตอบคำถามที่ตามมาทันทีว่า การขยับบนระนาบแปลเป็นผลจริงได้ไหม และเป็นสะพานไปหา cost model ของ RQ2

ต้องอ่านแยกจากหัวข้อ 3 ให้ชัด ตัวเลขในส่วนนี้เป็นผลลัพธ์ ไม่ใช่นิยามของ speculatability การเอาความเร็วมานิยามว่า workload ไหน high-speculatability คือ circular reasoning ในที่นี้จึงใช้เป็นเพียงการยืนยันภายหลัง

  • L/S คือ accepted length ใช้เมื่อ target ยาวเกิน 32 token
  • acc/tok คือ accepted token ต่อ target token ใช้เมื่อ target สั้น เพราะคำตอบ SQuAD ยาวราว 3 token ทำให้ L/S กระโดดเป็นขั้นจนอ่านไม่ได้

ผลโดยสรุป การขยับไปทางขวาในรูป B แปลเป็นผลจริงได้ในทุก dataset ที่มี group key โดยส่วนต่างจากคู่เทียบอยู่ที่ 1.10 ถึง 3.07 เท่าสำหรับ scope group และ 3 จาก 6 dataset ได้ผลดีขึ้นทั้งที่ corpus เล็กลง 12 เท่า
