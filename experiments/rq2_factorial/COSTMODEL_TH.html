RQ2 — Cost Model

ที่มาของสูตร speedup และทำไมแต่ละพจน์ถึงแทน speculatability กับ efficiency ได้

1. ทำไมต้องมี

simulator เดิมรายงาน speedup = L / S ซึ่งเป็นการนับ step ล้วน ๆ ไม่มีเวลาในสมการเลย เท่ากับสมมติว่า drafter ฟรี

ผลคือ retrieval สองแบบที่ออก draft เหมือนกันทุก bit ได้คะแนนเท่ากันเป๊ะ ทั้งที่ตัวหนึ่งช้ากว่า 206 เท่า แกน efficiency ซึ่งเป็นครึ่งหนึ่งของ RQ2 มองไม่เห็นด้วยตัววัดนี้ cost model คือการเอาเวลาใส่กลับเข้าไปโดยไม่ทิ้ง L/S

2. ที่มาของสูตร

decoding ปกติ ได้ 1 token ต่อ 1 forward pass อยากได้ L token ก็รัน L ครั้ง

T_baseline = L · t_v(1)

speculative รัน S ครั้ง (S < L) แต่ละรอบมีของแถมสองอย่าง คือเรียก drafter ราคา t_d และ verify B ตำแหน่งพร้อมกันแทนตำแหน่งเดียว ราคา t_v(B)

T_spec = t_build / R + S · ( t_d + t_v(B) )

t_build / R คือค่าสร้าง datastore จ่ายครั้งเดียวหารกับจำนวน request ที่ใช้ร่วมกัน ตัดทิ้งได้ในกรณี steady state

สมมติฐานเดียวของโมเดล verify หลายตำแหน่งใน pass เดียวแพงขึ้นเชิงเส้น

t_v(m) = t_v(1) · ( 1 + β(m − 1) )

β เล็กมากเพราะ decoding ติดคอขวดที่ memory bandwidth ไม่ใช่ compute ขน weight ขึ้นมาแล้วจะคูณ 1 ตำแหน่งหรือ 8 ตำแหน่งต้นทุนแทบไม่ต่าง ข้อนี้คือเหตุผลว่าทำไม speculative decoding ทำงานได้ตั้งแต่แรก

ค่าที่ใช้จริงคือ β = 0 ตามที่ตกลงกับที่ปรึกษาว่า “n token per 1 forward pass” คือ verify กี่ตำแหน่งก็นับเป็น forward pass เดียว ตัวส่วนจึงเหลือ 1 + ρ ค่า β > 0 เก็บไว้เป็น sensitivity ท้ายรายงาน ไม่ใช่ผลหลัก

หารกัน แล้วหารเศษส่วนด้วย t_v(1) ทั้งคู่

speedup = T_baseline / T_spec = (L/S) · t_v(1) / ( t_d + t_v(1)(1 + β(B−1)) )

speedup = (L / S)  ÷  ( 1 + ρ + β(B − 1) )   ρ = t_d / t_v(1)

ที่ β = 0  →  speedup = (L / S) / (1 + ρ)

ทุกขั้นเป็นพีชคณิตตรงไปตรงมา สมมติฐานมีที่เดียวคือรูปของ t_v(m)

3. แต่ละพจน์คืออะไร

พจน์ ความหมาย สมบัติของ
L / S ได้กี่ token ต่อหนึ่ง forward pass ข้อมูล
1 forward pass ที่ยังไงก็ต้องทำอยู่แล้ว —
ρ ส่วนเกินจากการเรียก drafter คิดเป็นสัดส่วนของ forward pass ระบบ
β(B−1) ส่วนเกินจากการ verify B ตำแหน่งแทนตำแหน่งเดียว ฮาร์ดแวร์
  • ตัวเศษไม่มีหน่วยเวลาเลย เปลี่ยน GPU เปลี่ยน implementation ค่านี้ไม่ขยับ มันขึ้นกับอย่างเดียวคือข้อความที่จะออกมาเดาได้แค่ไหน draft ผิดหมด → S = L → L/S = 1
  • ตัวส่วนไม่มี L ไม่มี S อ่านว่า “หนึ่ง speculative step แพงเท่ากับกี่ baseline step” เปลี่ยน dataset แล้วไม่ควรขยับ ซึ่งเป็นเงื่อนไขที่ต้องตรวจ ไม่ใช่สิ่งที่อ้างเฉย ๆ (รอบก่อนวัดได้ต่างกัน 0.4%)
  • หารกันเพราะทั้งคู่เป็นอัตราส่วนแบบคูณ ได้มา L/S เท่า จ่ายไป (1+ρ+β(B−1)) เท่า สุทธิคือหาร ตามมาด้วยเงื่อนไขคุ้มทุน L/S > 1 + ρ + β(B−1) คือ drafter แม่นอย่างเดียวไม่พอ ต้องแม่นกว่าราคาที่จ่ายไปเรียกมัน
  • ระวังเรื่องคำ ตัวส่วนคือค่าโสหุ้ย ไม่ใช่ efficiency ตัว efficiency จริงคือส่วนกลับ ห้ามพูดว่าตัวส่วนสูงแปลว่า efficiency สูง

4. การแก้ off-by-one

โค้ดเดิมเขียน t_v(m) = t_v(1)(1 + βm) ลองแทน B = 1 คือ verify ตำแหน่งเดียว ซึ่งก็คือ decoding ปกติเป๊ะ ควรได้ t_v(1) แต่สูตรเดิมให้ 1.01 · t_v(1)

กระทบ ยังไง
อัตราส่วนระหว่าง cell ไม่กระทบ พจน์ตัดกัน ข้อสรุปเชิงเปรียบเทียบรอบก่อนยังยืน
speedup ดิบ ต่ำกว่าจริงราว 1%
budget sweep หา B ที่ดีที่สุด กระทบเต็ม จุดยอดอ่านจากพจน์ค่าปรับนี้ตรง ๆ และเมื่อตั้ง β = 0 ก็ไม่มีจุดยอดเหลือ ทิ้งผลนี้

แก้ที่ TargetLatencyModel.step_latency_ns พร้อม test ยึดไว้ว่า t_v(1) ต้องเท่ากับ t_verify_1_ns เป๊ะ

5. อะไรวัดจริง อะไรยังเดา

ตัวแปร สถานะ หมายเหตุ
L, S วัดจริง นับจาก simulator ตรง ๆ
t_d วัดจริง จับเวลาบน CPU หัก overhead ของตัวจับเวลาแล้ว
t_v(1) สมมติ 20 ms ประมาณจากโมเดล 7B บน GPU ผู้บริโภค
β ตั้งเป็น 0 ตามข้อตกลง n token per 1 forward pass ไม่ใช่การเดาแล้ว แต่เป็นการนิยามหน่วย

ผลของการตั้ง β = 0 คือต้องทิ้ง budget sweep ถ้าไม่มีค่าปรับกับ B แล้ว L/S โตตาม B เรื่อย ๆ จุดยอดหายไป จุดยอดที่รอบก่อนรายงานจึงเกิดจาก β = 0.01 ที่เดามาล้วน ๆ

ที่เหลือคือ ρ ซึ่งตอนนี้คร่อมสองเครื่อง (t_d จาก CPU หารด้วย t_v(1) ที่สมมติเป็น GPU) ลำเอียงเข้าข้าง on-the-fly เพราะการสแกนคือการเทียบ tensor แบบขนานที่ได้ประโยชน์จาก GPU ส่วนการเปิด index คือการไล่ pointer ที่ไม่ได้อะไรเลย จึงรายงาน ρ เป็นแกนกวาด ไม่ใช่จุดเดียว

6. สรุป

  • สูตรมาจากการหารเวลาสองอันแล้วจัดรูป สมมติฐานมีที่เดียว
  • ตัวเศษไม่มีเวลา ตัวส่วนไม่มีข้อมูล การแยกนี้คือเหตุผลทั้งหมดว่าทำไม RQ2 ถึงถามคำถามแบบนี้ได้
  • speculatability เป็นเพดาน วิศวกรรมขยับไม่ได้ efficiency บอกว่าเข้าใกล้เพดานได้แค่ไหน
  • ที่ β = 0 เหลือ speedup = (L/S)/(1+ρ) ซึ่งมีตัวแปรที่ต้องวัดแค่สองตัว
  • กฎที่ได้จากสมการตรง ๆ วัด ρ ก่อนเสมอ ถ้าเกือบศูนย์ แปลว่า retrieval ฟรีอยู่แล้ว ไปแก้ datastore ไม่ต้องแตะโค้ด drafter
